description: Clarify ambiguous requirements BEFORE writing any code — enumerate ambiguities, ask the user structured questions, document the agreed spec with acceptance criteria and ubiquitous language. Use at the start of every feature request

実装を始める**前に**仕様の曖昧な点を洗い出してユーザーに確認し、合意した仕様を文書化する。「推測で実装して後で直す」を禁止するためのスキル。

## 原則

- **曖昧さは負債。** 推測 1 つにつき手戻り 1 回のリスクがある。確認コストは常に手戻りコストより安い
- **質問は具体的な選択肢で。** 「どうしますか?」ではなく「A / B / C のどれですか。推奨は A、理由は…」
- **一度に聞く。** 質問を小出しにしてユーザーを何度も往復させない。最初に全ての曖昧点をリストアップしてからまとめて確認する
- **答えは文書に落とす。** 会話ログは仕様書ではない

## 手順

### 1. 要求を分解して曖昧点を列挙する

以下の観点で要求を走査し、複数の解釈がありうる点を全てリストアップする:

| 観点 | 典型的な曖昧点 |
|------|--------------|
| ドメインルール | バリデーションの境界値(文字数上限、金額の範囲)、一意性の範囲、丸め方 |
| 状態遷移 | どの状態からどの状態に遷移できるか。逆方向の遷移(完了の取り消し等)は許すか |
| エッジケース | 空リスト、重複、同時操作、0件・上限到達時の挙動 |
| エラー時の挙動 | 失敗をユーザーにどう見せるか。リトライするか。部分的成功を許すか |
| 時刻・タイムゾーン | 「期限」は日付か日時か。判定はローカルか UTC か |
| UI の挙動 | 楽観的更新か確定後更新か。ローディング・空状態の表示。ルーティング(新規画面かダイアログか) |
| 永続化 | データはどこに保存するか(localStorage / API / IndexedDB)。既存データの移行は必要か |
| スコープ | 今回やらないことは何か。「ついで」に見える隣接機能は含むか |

### 2. AskUserQuestion でまとめて確認する

- 曖昧点ごとに 2〜4 個の具体的な選択肢を提示する
- 推奨がある場合は先頭に置き「(推奨)」を付け、理由を description に書く
- 自明な点(コードや慣習から一意に決まる点)は聞かない — デフォルトを採用して仕様書に明記すればよい
- 質問が 4 個を超える場合は重要度順に分割して複数回に分ける

### 3. 仕様書を書く

`docs/specs/{feature-name}.md` に以下の構成で書く:

```markdown
# {機能名}

## ユビキタス言語
| 用語 | 型名 | 意味 |
|------|------|------|
| 期限 | DueDate | TODO を完了すべき日付。日付のみ(時刻なし)、ローカルタイムゾーンで判定 |

## 決定事項
- 期限は過去日を許可しない(ユーザー確認済み 2026-07-13)
- 期限切れ TODO は削除せず「期限切れ」表示にする

## 受け入れ条件(Given / When / Then)
1. Given 有効な TODO がある When 明日の日付を期限に設定する Then 期限が保存され一覧に表示される
2. Given 期限が今日より前 When 期限を設定しようとする Then PastDate エラーが返り保存されない
...

## スコープ外
- 期限通知(プッシュ・メール)は今回含まない
```

- 受け入れ条件はそのまま**テストケースに変換できる粒度**で書く(Phase 3 の TDD で 1 条件 = 1 テスト以上に対応させる)
- ユビキタス言語の用語は、そのまま型名・コンパニオン名になる(`DueDate` VO 等)

### 4. 承認を得てから終了する

仕様書の要点(決定事項と受け入れ条件)を提示し、ユーザーの承認を得る。承認前に実装・設計を始めない。実装中に新たな曖昧点が出たら、このスキルに戻って仕様書を更新する。

## アンチパターン

- ❌ 「一般的にはこうなので」と確認せず実装する — 一般論とこのプロダクトの要求は別物
- ❌ 曖昧点を「TODO コメント」にして先に進む
- ❌ 選択肢のない開放質問を投げてユーザーに設計させる
- ❌ 確認した内容を文書化せず、会話の中だけで済ませる
